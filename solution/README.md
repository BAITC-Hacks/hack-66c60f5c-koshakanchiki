# Beeline Tariff Marketing Campaigns — команда «Кошаканчики»

Локальный агент выбирает тарифные кампании по **чистому приросту ARPU после
расходов на контакты**. История задаёт порядок исследования, а оценки эффекта
получаются из пилотов текущей среды. Данные кейса синтетические.

## Быстрый запуск

Проверенное окружение: Python **3.12.14**, NumPy **2.5.3**, pandas **3.0.6**.
Все команды ниже выполняются из папки `solution/`:

```bash
cp ../project-context/case-files/*.csv .
cp -R ../project-context/case-files/data .
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python local_eval.py
python local_eval.py --runs 10
python -m unittest discover -p 'test_*.py'
python validate_solution.py --json validation_results.json
python make_submission.py
```

Первые две команды восстанавливают датасеты из отслеживаемого исходного пакета
после чистого клонирования: копии CSV в `solution/` исключены из Git.
Код решения и этот README при этом не перезаписываются.

`agent.py` экспортирует класс `Agent` с методом `act(env) -> list[dict]`.
Среда передаётся организатором; для локальной проверки служит выданный
`mock_environment.py`. Файл `submission.csv` генерируется официальной командой
`make_submission.py` при seed **42**. На судействе агент заново исследует среду
и может вернуть иной план.

LLM, API-ключи и сетевые вызовы для работы не нужны. Зависимости ограничены
NumPy и pandas; библиотек обучения uplift-моделей нет.

## Устройство решения

| Файл | Назначение |
|---|---|
| `agent.py` | Пилоты, журнал ответов, обновление оценок, контроль остатков и возврат кампаний |
| `beliefs.py` | Независимые Gaussian posterior для действий и общие детерминированные выборки |
| `candidates.py` | Ячейки аудитории, ID-префиксы ARPU, исторические ранги и каталог действий |
| `historical_candidates.json` | Переносимые агрегаты истории: формула ранга, support и SHA-256 источника |
| `planner.py` | Основной простой портфель MVA, точный симулятор и сохранённый экспериментальный вариант |
| `planner_mva.py` | Сохранённая отдельная контрольная версия планировщика участника команды |
| `report.py` | Необязательное объяснение уже готового плана; не вызывается из `Agent.act` |
| `validate_solution.py` | Отдельный тестовый стенд: контракт, статистика, скоринг и воспроизводимость |
| `compare_policies.py` | Парное сравнение с неизменяемой MVA-версией агента из Git |

Вклад участника Hilexa из коммита `91a1251` сохранён побайтово в
`planner_mva.py` и `report.py`; `test_planner_mva.py` изменяет только имя импорта.
Рабочий агент использует простой `planner.build_portfolio`; сложный
`build_posterior_portfolio` сохранён для аудита отклонённого эксперимента и
из `Agent.act` не вызывается. `report.explain_plan(plan, summary)`
можно вызвать отдельно после экспорта. Он всегда умеет сформировать локальное
объяснение; LLM используется только при отдельном вызове, установленном
необязательном SDK `openai` и `OPENAI_API_KEY` в окружении. Ошибка SDK/API
возвращает локальный текст и не влияет на CSV.

Действие — `(current_tariff, arpu_segment, target_tariff)`. Потребление данных
и звонков используется для отбора исполнимых подгрупп, но не создаёт отдельную
оценку эффекта: в публичной механике эффект одинаков внутри такой ячейки.
Текущий baseline `predicted_arpu` используется без обрезки выбросов.
В выданном профиле 100 записей с отсутствующим текущим тарифом или ARPU-сегментом
не включаются в каталог; широкие фильтры для их захвата не используются.

Исторический ранг равен
`support/(support+10) * median(clip(next_ARPU/prev_ARPU - 1, -1, 3))`.
Удаляются точные дубли и строки с `prev_ARPU < 100`; интервалы сегментов
совпадают с публичным mock. Ранг не является causal-оценкой и не увеличивает
точность prior. Каталог сохраняет альтернативы вне HIGH и без исторической
поддержки. При отсутствии пригодной истории используются справочные кандидаты
и нулевая ранговая информация.

Эффект хранится на шкале SMS: начальный prior `Normal(0, 0.25²)`. Для пилота
канала `c`, фактического `n` и наблюдения `y`:

```text
h = multiplier[c] / multiplier[sms]
R = 0.804² / n
v_new = 1 / (1/v + h²/R)
mu_new = v_new * (mu/v + h*y/R)
```

Отрицательные наблюдения сохраняются. Непригодные ответы не обновляют posterior;
`actual_n < 10` допустим, если законный запрос 10 попал в маленькую аудиторию.
Среднее и стандартное отклонение масштабируются при смене канала. `Beliefs`
также поддерживает общие posterior-выборки при одинаковой случайности;
они используются сохранённым экспериментальным планировщиком.

Разведка проводится SMS-пилотами одной ячейки: до **8×120** на обзор и
**4×180** на уточнения, причём в фазе уточнения действие повторяется не более
одного раза. Текущая версия расходует не более **12 пилотов, 1 680 контактов,
6 720 денег**. Это потолок, а не обязательный расход: остатки берутся из
публичного env после каждого ответа. Проектный резерв `4×200` (общий потолок
16 / 2 480 / 9 920) и one-step VoI не включены без подтверждения их пользы.

Финал сравнивает push, SMS и digital_ads по прибыли и неопределённости.
Начальный осторожный порог — `(mu - sd) * ARPU_sum - contact_cost > 0`.
Call выключен: при насыщении конверсии линейный перенос с дешёвых каналов
неидентифицируем. Простой MVA-планировщик выбирает целые ячейки тремя жадными
стартами (общий net, net на контакт и SMS-first), не повторяет финальную ячейку
и использует фактические ARPU-префиксы. Data/call-подгруппы нужны для fallback.
Пилоты расходуют общие ресурсы и входят в итоговый результат; их расходы
учтены остатками env. Их неизвестные ID не восстанавливаются. Полная оценка
ожидаемых пересечений и utility по posterior-выборкам осталась только в
экспериментальном варианте после непройденного критерия качества хвостов.

Планировщик воспроизводит порядок публичного scorer: фильтры → сортировка ID →
cap 5 000 → оставшиеся контакты → доступный денежный бюджет. Повторные контакты
оплачиваются, а прирост абонента считается по лучшему дошедшему воздействию,
включая отрицательные эффекты. Возвращается 1–10 непустых строк с семью
экспортируемыми полями; отсутствующие фильтры — Python `None`.
Fallback выражается допустимыми фильтрами, без выдуманного финального `n_customers`.

## Проверки и воспроизводимость

Официальный `local_eval.py --runs 10` меняет шум и выборку пилотов в **одном**
mock-мире. Положительный результат на нём не гарантирует положительный результат
на скрытой модели судейства.

`python validate_solution.py` отдельно проверяет:

- Gaussian-формулу, перенос дисперсии каналов, знак отрицательных наблюдений,
  отклонение неверных ответов и фиксированные общие posterior-выборки;
- исходные ARPU, сортировку ID, пустые ячейки и фактический пилот меньше 10;
- совпадение симулятора с официальным scorer, cap5000, повторы с отрицательным
  эффектом, обрезку по остаткам и бесплатный push при нулевом денежном бюджете;
- 1–10 исполнимых кампаний, формат `None`, ограничения пилотов и общие ресурсы,
  неизменность профиля и повторный `act` одного объекта Agent;
- Agent на аудитории из 7 человек, при нулевом бюджете, ошибке пилота и
  испорченном наблюдении после реального списания ресурсов;
- два побайтово одинаковых CSV из чистых процессов при seed42 без API-ключа.

Дополнительные команды:

```bash
python validate_solution.py --units-only
python validate_solution.py --worlds --json validation_worlds.json
```

`--worlds` выполняет **12 smoke-прогонов**: шесть заранее заданных семейств,
`world_seed=100`, `noise_seed=1000,1001`. Семейства: редкие победители, близкие
эффекты, слабые плюсы, все отрицательные, ошибочная история и победители вне HIGH.
Стенд создаёт собственные искусственные эффекты и передаёт агенту только
публичный API. Это проверка корректности на других эффектах, а не завершённое
парное сравнение или заявка на превосходство по переносимости. В полностью
отрицательном мире обязательные контакты дают ущерб; положительный net там
не является критерием.

Фактические результаты завершённых прогонов сохраняются JSON-отчётами через
`--json`, вместе с версиями библиотек и SHA-256 исходников. Стенд отклоняет
результат, если исходники менялись во время проверки. Времена относятся к
машине запуска. Прогноз posterior, зашумлённое наблюдение пилота и фактический
результат evaluator — разные величины.

## Зафиксированное парное сравнение

До возврата к контролю команда `python compare_policies.py --json comparison_results.json` сравнила
неизменённый `agent.py` MVA-коммита `a5084f32808ba4fa76b2ddf7203b50def38c5be6`
с замороженным вариантом V2, использующим полный posterior-планировщик.
Воспроизводимый runtime-снимок V2 сохранён тегом **`posterior-v2-evaluated`**
(исходный коммит `afc14d3`). Текущий `Agent` использует простой MVA: повторный
запуск скрипта в текущей ветке сам по себе не воссоздаёт отклонённый V2.
Обе политики использовали одинаковые текущие `beliefs.py`, `candidates.py` и
исторический артефакт. SHA-256 исходников сохранены в
[`comparison_results.json`](comparison_results.json); во время проверки они
не менялись. В каждой паре совпали запросы **и наблюдения** всех пилотов.

Объём выбран до просмотра результатов по измерению времени одного отдельного
технического прогона: **6 семейств × 5 миров × 20 шумовых seed = 600 пар,
1 200 запусков**. `world_seed=100…104`, `noise_seed=1000…1019`. Выполнение заняло
323 с. Для bootstrap использованы средние различия внутри каждого из 30 миров,
10 000 повторов с seed42; миры имеют одинаковый вес.

| Проверка V2 относительно MVA | Результат |
|---|---|
| Среднее изменение общего net | +38 813 |
| 95% bootstrap-интервал среднего изменения | [+19 865; +60 274] |
| Время V2 `act`: P95 / максимум | 0,788 с / 1,128 с |
| Порог качества хвостов по всем семействам | **Не пройден** |

Причина отказа по заранее заданному критерию: в семействе ошибочной истории
P10 снизился с **431 136** до **332 650** (−98 486), при допустимом снижении
14 094. CVaR10 и доля отрицательных результатов этого семейства не изменились;
остальные пять семейств прошли порог хвостов. Рост среднего не отменяет этот
отрицательный результат приёмки. Это сравнение собственных синтетических миров,
а не измерение скрытой модели организатора.

По этому результату рабочий `build_portfolio` возвращён к простому MVA-правилу;
обязательные исправления обработки ошибок и устаревшего плана сохранены.
Параметры по результатам этих миров не подбирались.

Финальный контроль с этими исправлениями отдельно проверен на **новых мирах
200…204**: снова 600 пар / 1 200 запусков, те же 20 шумовых seed и шесть
семейств. Это диагностика обязательных исправлений, без нового поиска
параметров. Повторить её для текущего агента:

```bash
python compare_policies.py --world-start 200 --timing-world 199 --diagnostic \
  --candidate-label mva_control_with_correctness_fixes \
  --json final_comparison_results.json
```

Отчёт: [`final_comparison_results.json`](final_comparison_results.json),
30 миров, 214 с, исходники неизменны. Среднее изменение net относительно
исходного MVA **+13 477**, 95% bootstrap-интервал **[+3 337; +26 348]**.
Все шесть критериев хвостов пройдены. Доля отрицательных результатов обеих
политик на этом намеренно жёстком синтетическом наборе одинакова — **27,17%**.
В четырёх семействах результаты совпали; улучшения получены в редких
победителях и полностью отрицательных мирах после исключения устаревших планов.
Время финального `act`: **P95 0,178 с**, максимум **0,341 с**.

## Состав поставки

Нужны все модули решения, `historical_candidates.json`, `requirements.txt`, этот
README и воспроизводимый `submission.csv`. Для локального запуска также нужны
выданные `environment.py`, `scoring_core.py`, `mock_environment.py`,
`local_eval.py`, `make_submission.py`, `customer_profile.csv`, справочники и
`data/`. Эти исходные файлы не модифицируются алгоритмом.

Агент использует только профиль, справочники, остатки ресурсов и `run_pilot`.
Тестовый стенд и официальный evaluator имеют отдельную сторону скоринга;
их модели эффектов и записи пилотных ID агенту не передаются.
После генерации CSV решение фиксируется в выданном репозитории.
По подтверждённому порядку команды сдача — **push ветки `team/agent` до 18:00
по Астане**.
