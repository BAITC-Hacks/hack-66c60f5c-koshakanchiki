# Выбор единой версии

Сравнение выполнено 23 сентября 2026 года по фактическим файлам двух папок, публичному коду задания и уточнению команды о пяти часах. Это сравнение проектов решения, а не измерение качества двух готовых агентов: готового `agent.py` в этих папках нет.

**Основа итоговой версии — `azamat-reserch-codex`.** Она точнее соблюдает текущий срок, ограничения API, экономическую цель и воспроизводимость. Полезные элементы из `azamat-reserch` перенесены в единую версию. Выбор сделан по содержанию документов, а не по авторству.

## Почему спорные места влияют на результат

**LCB процента и LCB прибыли отличаются.** Положительный валовый эффект может быть меньше цены контакта. Помимо финальных кампаний, в счёте остаются уже проведённые убыточные пилоты. Поэтому один коэффициент осторожности не гарантирует плюс на всех seed. [Формула net](<../amir-research/scoring_core.py#L241>).

**Лимиты связаны друг с другом.** При одном SMS деньги действительно не исчерпываются раньше 15 000 контактов. При ads/call деньги могут стать главным ограничением. Нулевой остаток бюджета не является критерием качества.

**Похожие шумные наблюдения не доказывают насыщение.** В опубликованной модели множители push/SMS/ads меньше единицы, а вероятность конверсии не превосходит единицы; насыщение этих трёх каналов не возникает. Для call оно возможно, но не означает отсутствия всякой дополнительной выгоды по сравнению с ads. [Формула конверсии](<../amir-research/scoring_core.py#L166>).

**Thompson sampling и ценность информации решают разные задачи.** Уверенно лучший вариант может продолжать выигрывать сэмплирование. Для выбора следующего эксперимента нужно учитывать, насколько он изменит конечное решение, и сколько ресурсов отнимет. Сравнение и применимый алгоритм вынесены в исследование разведки.

**Нельзя вычеркнуть произвольные ID из финальной кампании.** Можно вычеркнуть целую уже занятую ячейку либо построить непересекающиеся допустимые фильтры. Фактический состав и порядок отсечения необходимо считать по публичным правилам. [Исполнение кампаний](<../amir-research/scoring_core.py#L195>).

## Что сохранено из второй версии

1. Подготовка переносимого файла исторических агрегатов до запуска `act()`, с включением в комплект и fallback при отсутствии.
2. Карта ячеек с численностью, средней и суммарной ARPU для объяснения приоритетов разведки.
3. Работа в общей шкале эффекта для сравнения несатурирующих каналов, с явным исключением call из линейного переноса.
4. Разделение файлов между тремя участниками, ранний сквозной запуск и чистая проверка поставки.

Не переносим недоказанные гарантии, обязательное полное расходование бюджета и сетевую зависимость решения. Исследовательские улучшения отделены от обязательного MVP: пять часов не превращаются в неограниченную разработку.
