# План на 5 часов для трёх участников

К 1:15 должен работать сквозной агент, к 3:30 — версия для сдачи, в 4:15 прекращаем добавлять функции. Финальные 45 минут защищены под проверки и сдачу.

## Владельцы

| Участник | Что разрабатывает | Результат |
|---|---|---|
| 1. Данные и статистика | `candidates.py`: агрегаты, историческое ранжирование, оценки и неопределённость | Разнообразные кандидаты, правильные веса пилотов, осторожный net |
| 2. Агент и планирование | `agent.py`: `act(env)`, пилоты, ресурсы, кампании, каналы, fallback | Рабочий детерминированный агент |
| 3. Интеграция и сдача | Проверки, сравнение с шаблоном, `report.py`, README, зависимости, CSV | Воспроизводимый комплект и демонстрация |

Это будущие модули, а не уже реализованный код. Самого уверенного Python-разработчика поставить на роль 2, участника с опытом статистики — на роль 1. Роль 3 начинает проверки с первого часа.

## Расписание

| Время | Участник 1 | Участник 2 | Участник 3 | Контрольная точка |
|---|---|---|---|---|
| 0:00–0:15 | Проверяет поля профиля и истории | Разбирает API и шаблон | Настраивает окружение, сохраняет baseline | Согласованы структуры и владельцы файлов |
| 0:15–1:15 | Агрегирует ячейки, готовит переносимые исторические агрегаты и разнообразные target | Делает простой цикл SMS-пилотов, выбор по результату и ограниченный финал | Проверяет формат, сегменты; запускает evaluator и генератор CSV | Работает весь путь от входа до CSV |
| 1:15–2:30 | Добавляет слабый prior, правильный SE и обновление | Делает адаптивный следующий пилот, остановку и непересекающиеся кампании | Проверяет отрицательные пилоты, остатки ресурсов, повторный запуск; пишет README | Пилот меняет следующее действие и итог |
| 2:30–3:30 | Проверяет лидеров и 1–2 настройки осторожности | Сравнивает push/SMS/ads, разделяет сегменты, учитывает отсечение по ID | Сравнивает версии на одинаковых seed, запускает `--runs 10`, измеряет время | Выбрана рабочая версия |
| 3:30–4:15 | Проверяет смысл цифр и объяснений | Исправляет ошибки, проверяет fallback и дедлайн | Доводит README и отчёт; LLM-объяснение только при готовом ядре | Заморозка функций |
| 4:15–5:00 | Сверяет расчёты отчёта | Помогает с блокирующими ошибками | Чистый запуск, CSV дважды, комплект и репетиция | Проверенная сдаваемая версия |

Десять seed запустить к 2:30 параллельно с документацией. Если это занимает неожиданно долго, сначала разобраться с задержкой; не съедать резерв сдачи новыми функциями.

## MVP

- Исследуем `current_tariff × arpu_segment → target_tariff`, без индивидуальной ML-модели.
- История задаёт очередь; численный эффект уточняется пилотами.
- Полный агрегированный каталог сохраняется; короткая очередь содержит альтернативы без истории. Нет безусловного отсева всех ячеек меньше 150 человек.
- SMS-разведка: до `8×120 + 4×180 + 4×200 = 2 480` контактов. Резервные четыре пилота уже входят в общее число 16.
- Один лучший target на ячейку; финальные сегменты преимущественно непересекающиеся.
- Сравниваем чистую прибыль push/SMS/ads, учитываем все ограничения и реальный порядок отсечения аудитории.
- При запасе времени сравниваем несколько начальных планов и простые замены через один симулятор. Более сложная ценность информации — следующая итерация после рабочего цикла.
- Один запуск, CSV, Markdown-отчёт и README.

Не входят в эти пять часов: call с отдельными пилотами, сложные пересечения, новый UI, обучение большой модели, RAG, микросервисы, автоматическая смена стратегии через LLM. Это ограничение объёма разработки, а не утверждение, что исключённые варианты всегда невыгодны.

## Контракты

```text
Candidate: id, filters, target_tariff, channel,
           audience_count, audience_arpu_sum, historical_rank
PilotObservation: candidate_id, filters, target_tariff, channel,
                  actual_n, observed_lift_ratio, cost
Estimate: candidate_id, mean_ratio, posterior_sd, actual_contacts

build_candidates(profile, tariffs, channels, history) -> candidates
update_estimate(previous, observation) -> estimate
choose_next_pilot(candidates, estimates, resources) -> request | None
select_campaigns(profile, candidates, estimates, resources) -> campaigns
Agent.act(env) -> list[dict]
```

Пока участник 1 готовит данные, участник 2 работает с временным списком валидных кандидатов из `env`; затем подключает `build_candidates`. Только участник 2 вызывает `env.run_pilot`. Отчёт читает журнал готового запуска и не повторяет пилоты.

Оригинальные evaluator и среду не менять. Импортируемые собственные модули включить в комплект. В финальные кампании не добавлять внутреннюю статистику, произвольные ID и несуществующий параметр `n_customers`.

Подготовленный из публичной истории собственный артефакт также включить в комплект. Проверить его загрузку относительно файла агента и запуск без него через fallback. Карта дальнейших задач — в `07-improvement-roadmap.md`; она не увеличивает срок MVP.

## При отставании

| Ситуация | Действие |
|---|---|
| К 1:15 нет сквозного запуска | Все помогают запуску; отчёт и улучшения ждут |
| К 2:30 адаптивность ломается | Двухступенчатая разведка: обзор и подтверждение по результатам |
| К 3:30 разделение SMS/ads нестабильно | Выбирать канал на целую допустимую ячейку; не расходовать бюджет любой ценой |
| Проблемы с LLM или ключами | Локальный отчёт, тот же CSV |
| Ошибка после 4:15 | Только блокирующее исправление или последняя проверенная версия |

В последние 45 минут: до 4:35 чистый запуск и сверка CSV; до 4:45 комплект и репетиция; последние 15 минут — резерв. Участник 1 объясняет данные, участник 2 — агента, участник 3 — воспроизводимость и замеры. Владелец сдачи — участник 3; другой участник проверяет комплект.
