# Итог трёх исследований: Beeline Tariff Marketing Campaigns

**Рекомендуем строить локального статистического агента: разнообразные тарифные гипотезы → однородные пилоты → обновление эффекта и неопределённости → портфель исполнимых кампаний по чистому результату.** Основа — конструкция Азамата, уточнённая аудитом Амира и проверкой применимости методов Мираса.

Это завершённый синтез исследований на **23.09.2026**, с повторёнными расчётами и новыми проверками. Готовый `Agent.act`, его сравнительный балл и сдача — следующий этап. Превосходство всей будущей стратегии ещё не измерено.

## Решение в порядке реализации

1. **Каталог действий.** 63 известные ячейки `current_tariff × arpu_segment`, по 20 других тарифов: 1 260 действий. История задаёт порядок исследования; очередь содержит также неизвестные target и альтернативы вне HIGH. Не обучать индивидуальный uplift на истории состоявшихся переходов.
2. **Слабый prior и точные измерения.** Начало `Normal(0, 0.25²)` на шкале SMS; пилоты только одной ячейки. Использовать `observed_lift_ratio`, фактическое `n`, шум `0.804/√n`. Отрицательные наблюдения сохранять. Масштабировать и среднее, и ошибку при смене канала.
3. **Дозированная разведка.** Начальный проверяемый режим Азамата: до `8×120 + 4×180 + 4×200` SMS-контактов, с адаптивным выбором уточнений и остановкой. Потолок — 16 пилотов, 2 480 контактов, 9 920 денег. Это конфигурация для первого сравнения, не найденный оптимум. Одношаговую ценность информации оставить претендентом на улучшение.
4. **Совместный выбор аудитории и канала.** Сравнивать push/SMS/ads по денежному результату после расходов. Call отложить до отдельного подтверждения: линейный перенос может ошибаться из-за насыщения.
5. **Исполнимый портфель.** Точные фильтры, сортировка по ID, обрезки и остатки; непересекающиеся финальные аудитории, оценка случайных пересечений с пилотами. Несколько жадных стартов и локальные замены, единая оценочная функция для всех вариантов. От 1 до 10 строк; при плохих эффектах — ограничение ущерба.
6. **Воспроизводимость.** Python + NumPy/pandas, собственный журнал пилотов, фиксированная случайность, переносимый файл исторических рангов. LLM — необязательное объяснение готового плана. Затем проверки официального evaluator, экспорта и отдельных миров эффектов.

Точные формулы, выбор следующего пилота и обработка сбоев: [ALGORITHM.md](ALGORITHM.md).

## Что взяли у каждого

| Исследование | Сильная часть, вошедшая в решение | Существенная поправка |
|---|---|---|
| Амир | Аудит данных/API, денежная экономика каналов, фактическое n, отрицательные эффекты и пересечения | Ранние PoC-баллы не воспроизведены; история не становится известной конверсией |
| Азамат | Конкретный лёгкий алгоритм, разнообразный каталог, поставка агрегатов, несколько стартов и локальный поиск | One-step не победил во всех toy-мирах; 456 исторических действий относятся к своей очистке |
| Мирас | Отбор по денежной прибыли, явный учёт вредных воздействий, проверка на отложенных данных, отделение LLM от численного выбора | TwoModels требует отсутствующих treatment/control; OmegaUCB и power analysis нельзя переносить напрямую; `net/cost` ломается на push |

Полная карта альтернатив, доказательств и условий пересмотра: [DECISIONS.md](DECISIONS.md).

## Подтверждённые ограничения

По [ТЗ, §§7–9](../project-context/case-files/PARTICIPANT_GUIDE.md#7-must-have) и публичному коду: бюджет **100 000**, **15 000 контактов вместе с пилотами**, не более **20 пилотов**, запрос **10–200** человек, **1–10 финальных кампаний**, максимум **5 000** человек в строке. Агент должен провести пилот и использовать его результат. Основное ТЗ даёт **10 минут** на исполнение; внутренний дедлайн 240 секунд помещается и в пятиминутный лимит из комментария шаблона.

Цена контакта / множитель: push **0 / 0.50**, SMS **4 / 0.65**, ads **22 / 0.85**, call **160 / 1.20**. Повторы оплачиваются полностью; gross клиента — лучший из дошедших эффектов, даже если он отрицателен. Бесплатный push также может причинить ущерб.

Официальное положение повторно прочитано по HTTP, включая встроенный текст: **разработка 23 сентября 13:00–18:00 по Астане, README обязателен**. Подтверждены пп. 3.5, 5.4.13–16; девять часов и необязательный README из раннего ТЗ не использовать для сдачи. [Положение Astana Hub](https://edu.astanahub.com/hackathons/df4743f5-c492-415c-b45a-1f13adb78e06?tab=regulations).

## Что проверено сейчас

- Все **19** проверок механики Амира повторились; аудит CSV и оба числовых эксперимента Азамата совпали с сохранёнными результатами.
- **451 и 456** — разные правила очистки истории. После дедупликации и `prev_ARPU ≥ 100` получены **12 699 строк и 451 действие**. История не пересекается по ID с текущей аудиторией.
- Исходные **20** задач портфеля и новые **80** задач с другими эффектами/ограничениями подтвердили пользу нескольких стартов и замен. В 20 новых отрицательных задачах разрешён пустой план и все методы равны нулю: обязательный fallback этим не проверен.
- В **1 200** повторённых toy-прогонах one-step лучше fixed по среднему в трёх мирах, хуже примерно на **2,9%** в мире слабых положительных эффектов. Здесь fixed — `20×120`; с рекомендуемой фазовой сеткой прямого сравнения ещё нет. Сложный выбор пилотов не включаем автоматически.
- Проверены перенос дисперсии, неидентифицируемость call, формула ожидаемых пилотных пересечений с отрицательными эффектами и смещение от обнуления отрицательных наблюдений.

[VALIDATION.md](VALIDATION.md) разделяет выполненные проверки и следующий этап; там же — четыре оставшихся вопроса. Машинные доказательства: [скрипт](evidence/verify.py), [результаты](evidence/results.json), [проверенные внешние источники](evidence/sources.json). Отдельные черновики удалены после синтеза. Нужные [эксперименты](evidence/experiments/README.md) и [эталонные результаты](evidence/expected.json) перенесены сюда; исходный пакет кейса сохранён в `project-context/`.

Главные риски: за 20 пилотов нельзя проверить 1 260 действий; историческое ранжирование может обмануть; осторожный posterior не гарантирует прибыль; реальные ID пилотов неизвестны. Новая официальная версия пакета и закрытые уточнения организаторов публичным поиском не установлены — техническую версию нужно сверить перед реализацией.
