# Правила хакатона и сроки

Проверено 23 сентября 2026 года по [положению на платформе Astana Hub](https://edu.astanahub.com/hackathons/df4743f5-c492-415c-b45a-1f13adb78e06?tab=regulations), [официальному лендингу](https://hackalem.ai/), [инструкции участника](https://drive.google.com/file/d/105Rnhzg3Q5tKjfGZIddRqY13kmq_w4r_/view) и [локальному разбору первоисточников](../amir-research/EXTERNAL_ORGANIZERS_TELEGRAM.md). При изменениях на платформе ориентироваться на актуальный первоисточник.

## Главное для команды

| Вопрос | Правило и источник |
|---|---|
| Когда проходит разработка | 23 сентября 2026, **13:00–18:00 по Астане**; положение, пп. 3.5, 5.4.13. Официальным окончанием считается 18:00 независимо от блокировки интерфейса. |
| Где вести работу | Основная разработка и история изменений — в репозитории команды, выданном платформой; положение, пп. 5.4.9, 5.4.11. Наличие этого исследовательского репозитория не доказывает, что он и есть выданный репозиторий. |
| Промежуточные результаты | Каждый час нужен подтверждаемый результат; положение, п. 5.4.8. |

| README | В репозитории нужен актуальный README с назначением, архитектурой, технологиями и инструкцией воспроизводимого запуска/проверки; положение, п. 5.4.15. |
| Личный вклад | Правила зачёта требуют вклад каждого участника и учёт входов/выходов; [PDF правил](event-docs/Правила%20зачета%20участия.pdf). |
| AI-инструменты | По положению, п. 5.4.12, разрешены разные инструменты; Codex обязателен, только если это явно требует конкретная задача. |

## Сдача и последующие этапы

По [инструкции участника](https://drive.google.com/file/d/105Rnhzg3Q5tKjfGZIddRqY13kmq_w4r_/view) код нужно отправить в выданный GitHub-репозиторий, затем на странице трека выбрать кейс и выполнить действие **«Сдать решение»** с названием и описанием. Локального `submission.csv` для организационной сдачи недостаточно.

[Официальный лендинг](https://hackalem.ai/) указывает проверку решений 24–28 сентября, Demo Day 29 сентября и награждение 1 октября. Техническая метрика Beeline — чистый прирост ARPU, но положение также содержит отдельные критерии Demo Day: ценность, качество результата, инновационность, масштабирование и презентация (п. 5.7). Высокий `net_value` сам по себе не гарантирует итоговое место.

## Расхождения, которые нельзя пропустить

- Начало локального [ТЗ кейса](case-files/PARTICIPANT_GUIDE.md) говорит «9 часов», а действующее положение задаёт соревновательную часть 13:00–18:00. Планировать по официальному окну.
- Локальное ТЗ считает README необязательным для технического кейса, но положение требует его для проверки проекта. Включить README в сдачу.
- Лендинг всё ещё пишет об обязательном Codex; более позднее положение разрешает любые AI-инструменты с оговоркой для конкретного кейса. При необходимости проверить требования карточки Beeline.

Полный аудит дат, формулировок и доступности источников: [исследование организаторских материалов](../amir-research/EXTERNAL_ORGANIZERS_TELEGRAM.md).
